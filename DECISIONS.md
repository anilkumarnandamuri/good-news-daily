## D003 — Legacy feed adapter for unmigrated routine feed items (2026-10-15, agy/gemini-3.8-flash-high)
- Decision: Add a transitional legacy feed adapter in `app.js` upon fetching `data/news.json` to derive `summary_status` as `'paired'` when both `sum_en` and `sum_te` are non-empty strings (and `'excerpt'` with blank summaries otherwise), while keeping `reader.js` strict so saved items without `summary_status` safely fall back to excerpts.

## D004 — Controlled test fixtures and summary cache eviction (2026-10-15, agy/gemini-3.8-flash-high)
- Decision: Use Playwright network routing (`context.route`) with controlled legacy feed fixtures for UI regression tests, isolate optional browser dependencies in test modules from standard unittest discovery, and restore bounded 7-day cache eviction for departed stories in `scripts/summarize.py`.
- Why:
  - Depending on live `data/news.json` in browser tests makes them brittle across routine feed refreshes, especially when the first story legitimately lacks summaries or after summarize v6 eliminates legacy-format items.
  - Direct imports of pytest/playwright caused `python3 -m unittest discover` to fail in basic Python environments lacking test packages.
  - Omission of cache eviction allowed `data/summaries.json` to grow indefinitely across routine refreshes.
- Alternatives rejected:
  - Modifying live `data/news.json` or pinning test stories to specific mutable feed indices: Flaky across scheduled data updates.
  - Evicting all departed stories immediately (0-day retention): Breaks readers accessing recently departed stories from bookmarks/history and discards cached translations if a story temporarily drops and reappears.

## D005 — Cache eviction for invalidated summaries and pytestmark browser test skipping (2026-10-15, agy/gemini-3.8-flash-high)
- Decision: Evict rejected entries from the summary cache upon source or description changes (`cache.pop(item["id"], None)`), and configure missing browser dependency handling via `pytestmark` skip markers rather than raising `pytest.skip` at module import.
- Why:
  - If a publisher updates an article's description with corrected facts, failing to evict the invalidated cache entry allowed subsequent standalone builds (where `desc` is no longer present) to fall back to the outdated summary and silently restore invalid facts.
  - Raising `pytest.skip` at module import level raises `_pytest.outcomes.Skipped`, which is not an instance of `unittest.SkipTest`. In environments where `pytest` is present but `playwright` is absent, running `python3 -m unittest discover` failed on module import. Setting `pytestmark` skips the tests cleanly in `pytest` while allowing `unittest discover` to import the file with zero errors.
- Alternatives rejected:
  - Marking invalidated summaries with an invalidation flag instead of deletion: Adds schema complexity when eviction already ensures clean re-summarization or explicit excerpt fallback.
  - Raising `unittest.SkipTest` at module level: Causes `pytest` to exit with status code 5 (no tests collected) when invoked on the single file.

## D006 — Voice player re-entrancy teardown, async cancellation, and opacity pulse animation (2026-10-15, agy/gemini-3.8-flash-high)
- Decision:
  1. Clear `activePlayer = null`, `activeBtn = null`, and `window.__readerPlayer = null` before invoking `player.destroy()` in `stopVoice()`, and guard event listeners with `player.destroyed || player !== activePlayer` checks.
  2. Invalidate pending `playVoice` asynchronous continuations across module/manifest loading by incrementing a `playRequestId` token on `stop()` / `stopVoice()` and aborting execution if `reqId !== playRequestId || R.hidden || !cur || cur.id !== story.id || !btn.isConnected`.
  3. Change `.r-listen.on` pulse animation to use `opacity: 0.85` instead of `transform: scale(1.03)`, and deduplicate `highlightSentence` scroll calls against the active highlight index.
- Why:
  1. Synchronous `destroy()` -> `stop()` -> `statechange` ('idle') previously re-entered `stopVoice()` while `activePlayer` was non-null, leading to call-stack exhaustion.
  2. Navigating away, closing the reader, or toggling playback while the voice module or manifest was fetching allowed stale continuations to instantiate background audio over subsequent stories.
  3. Infinite CSS keyframe `transform: scale(1.03)` kept the button's layout bounding box unstable across frames, preventing Playwright actionability checks from clicking the stop button during active MP3 playback. Opacity pulsing provides equivalent visual feedback without geometry mutation or layout thrashing.
- Alternatives rejected:
  - Using Playwright `force=True` on click: Rejected because real touch/mouse interactions also suffer when target elements oscillate geometry continuously.
  - Relying on setTimeout for async teardown: Brittle across varying network and device speeds.

## D007 — Summary load playback teardown, sample route verification, and optional browser test discovery (2026-10-15, agy/gemini-3.8-flash-high)
- Decision:
  1. In `reader.js`, invoke `stopVoice()` before calling `renderBody(it)` when asynchronous summary loading completes for an active story.
  2. In `reader.js`, verify `location.hash` still matches the target story id before invoking `open(id, found)` after asynchronous `getSampleNews()` resolves.
  3. In `tests/test_voice_reader.py`, make `pytest` and `playwright` imports optional inside `try...except ImportError` blocks with `pytestmark` skip markers, mirroring `test_legacy_feed_browser.py`, and isolate `test_voice_reader` during playwright-absent discovery checks in `test_compatibility.py`.
- Why:
  1. If a reader started playback on an initial render before summaries finished loading, replacing `rBody.innerHTML` without stopping detached the active audio controls, leaving invisible background playback and resetting the visible button to an idle state.
  2. If a user navigated away or closed the reader while sample news was fetching, the resolved lookup callback previously opened the original story regardless of the URL, corrupting reader state and overriding the user's route.
  3. Direct module-level imports of `pytest` and `playwright` caused `python3 -m unittest discover -s tests -v` to emit `_FailedTest` errors in basic environments lacking browser dependencies.
- Alternatives rejected:
  - Skipping the summary rerender while playing: Leaves outdated excerpt text and missing sentence spans permanently displayed for the session.
  - Relying on `cur` ID comparison without checking `location.hash`: Fails when the user closes the reader (`cur = null`), incorrectly reopening the story on hash `""`.

## D008 — Protected sentence splitter for legacy summary rendering and playback (2026-10-15, agy/gemini-3.8-flash-high)
- Decision: Introduce a unified `splitSentences(text)` function in `reader.js` (and expose it on `window.splitSentences`) that protects decimal points between digits (`/(?<=\d)\.(?=\d)/gu`) and common abbreviations/initialisms (`/\b(?:Mr|Mrs|Ms|Dr|Prof|Sr|Jr|St|vs|etc)\./giu` and `/\b(?:[A-Za-z]\.){2,}|\b[A-Z]\.(?=\s+[A-Z][a-z])/gu`) before splitting against sentence terminators `[^.!?।॥…]+[.!?।॥…]*|[.!?।॥…]+`, and use it consistently in both `block()` DOM rendering and `playVoice()` queue creation. Wrap dynamic import in `getVoiceModule()` in `try...catch`.
- Why: Previously, legacy stories without precomputed pairs in `data/summaries.json` were split naively on all punctuation characters including periods, corrupting decimal numbers such as `$16.8 billion` into `$16. 8 billion` in DOM text and generating separate broken speech chunks. Sharing a single protected splitter ensures rendered sentence spans and spoken queue chunks stay aligned without corrupting numerical or abbreviation data.
- Alternatives rejected:
  - Importing `chunkText` asynchronously from `voice/src/gn-voice.js`: Rejected because `block()` renders story cards and summary sections synchronously during initial page layout and route changes before dynamic ES modules can be imported.
  - Relying on CSS or string replacement post-split: Fragile and fails to preserve audio player chunk boundaries during speech playback.

## D006 — Extract-and-translate fallback and summary status preservation (2026-10-15, agy/gemini-3.8-flash-high)
- Decision: In `scripts/summarize.py` v6, fall back to the live extract-and-translate method (feed description + og/meta descriptions, 1:1 sentence machine translation) when the LLM hook is not enabled or fails, building aligned `pairs` directly without re-splitting. For existing v5 cache entries whose joined strings cannot be re-paired by `legacy_pairs` (sentence count mismatch or <4 sentences), preserve them as `sum_en`/`sum_te` with `summary_status = 'summary'`, and render `'summary'` status in `reader.js`/`app.js` like `'paired'`.
- Why:
  - Without the LLM hook configured, summarize v6 previously dropped ~107/115 stories to excerpt-only on every routine run because v5 cache entries had sentence counts that did not match `legacy_pairs` validation.
  - Building pairs directly from aligned per-sentence translation lists preserves exact 1:1 correspondence without fragility from re-splitting joined prose.
  - Retaining existing v5 cache entries under `summary_status = 'summary'` prevents discarding existing valid human-checked and machine translations, requires zero network requests for already-cached stories, and maintains complete bilingual coverage across routine refreshes.
- Alternatives rejected:
  - Dropping all non-re-pairable v5 cache entries to excerpts: Rejects over 90% of existing stories and violates the routine's zero-regression requirement.
  - Re-splitting joined strings with punctuation regexes: Introduces mismatch between English and Telugu sentence boundaries and breaks number alignment.
  - Making live network calls to re-summarize already cached stories: Wastes network bandwidth, slows down the routine, and risks API rate limits.

## D007 — Fallback time budget enforcement and routine simulation non-empty feed requirement (2026-10-15, agy/gemini-3.8-flash-high)
- Decision: Propagate the remaining time budget (`deadline - time.monotonic()`) down through metadata retrieval (`meta(url, timeout)`) and translation (`translate(text, sl, tl, timeout, deadline)`), checking the deadline between requests and between endpoints. In `tools/routine_sim.py`, require a non-empty simulated feed (`n_total > 0`) before accepting the all-stories-summarized alternative (`n_sum == n_total`).
- Why:
  - Without remaining deadline propagation, when translation endpoints or network requests are slow or timing out, a fallback triggered close to the 240-second routine deadline could continue for up to 128 additional seconds (fetching metadata plus six sentences across two translation endpoints), overrunning the routine time budget.
  - In `tools/routine_sim.py`, if RSS fetching completely failed for all feeds, `build.py` wrote an empty feed where `n_sum == n_total` evaluated to `0 == 0`, erroneously reporting PASS despite total loss of stories. Requiring `n_total > 0` ensures complete feed failures are caught and reported as failures.
- Alternatives rejected:
  - Allowing `extract_and_translate` to consume its own unconstrained timeout on each sentence: Overruns the routine budget when multiple stories or sentences experience slow network or endpoint outages.
  - Relying solely on `n_sum >= b_sum` in routine simulation: Rejects valid routine builds when the total number of stories naturally fluctuates downwards while all present stories are successfully summarized.

## D008 — Fallback support for 1–3 sentence summaries as summary_status 'summary' (2026-10-15, agy/gemini-3.8-flash-high)
- Decision: When the extract-and-translate fallback extracts 1–3 sentences (and all sentences translate successfully), validate each pair with `validate_pairs(pairs, min_sentences=1)`, store the resulting 1–3 aligned pairs in the cache with `summary_status = 'summary'`, and assign `summary_status = 'summary'` to the story. Keep 4–6 sentences as `summary_status = 'paired'`. Do not relax `validate_pairs` for the LLM hook path (which strictly enforces 4–6 sentence pairs). Re-tokenize Telugu words in `_tok` using `[\w\u0C00-\u0C7F]{3,}` so Telugu prose with combining vowel marks is not fragmented.
- Why:
  - In short news articles with only 1–3 extractable sentences, the live v5 summarizer generated valid 1–3 sentence bilingual summaries. In v6, `validate_pairs` required 4–6 pairs and threw `ValueError`, regressing 5 stories to excerpt-only in routine simulation (111/116 vs 116/116 in v5).
  - Storing 1–3 aligned pairs under `summary_status = 'summary'` preserves bilingual coverage across routine updates without regressions, avoids dropped stories, and caches the result for instant reuse without re-translation.
  - The LLM hook path retains the strict 4–6 sentence requirement (`min_sentences=MIN_SENTENCES`), ensuring LLMs produce standard-length summaries as designed.
- Alternatives rejected:
  - Relaxing `validate_pairs` to 1–6 pairs globally: Violates the contract that LLM-generated summaries must contain 4–6 sentence pairs.
  - Dropping short stories to `summary_status = 'excerpt'`: Regresses story summaries compared to the live v5 routine.

## D010 — Voice module failure recovery, speechSynthesis fallback, and fixed browser fixtures (2026-10-15, agy/gemini-3.8-flash-high)
- Decision:
  1. In `reader.js`, gracefully fall back to the existing `speechSynthesis` playback path via `speak(btn, fallbackText, lang)` when `getVoiceModule()` fails to load or import `VoicePlayer`. Reset `voicePromise = null` and increment a retry query token (`voiceLoadAttempt`) so failed module imports are not cached and subsequent user clicks re-attempt dynamic import without requiring a page reload. Never extend an undefined `VoicePlayer` class.
  2. In `tests/test_voice_reader.py`, decouple all browser tests from mutable routine data files by intercepting network requests to `data/news.json` and `data/summaries.json` using controlled test fixtures under `tests/fixtures/` (`news.json` and `summaries.json`). Include stories covering bilingual sentence pairs (`be4d5ceb60`), prebuilt MP3 manifest entries (`beb21be0b4`), legacy decimal preservation (`378259bf26`), and `summary_status: 'summary'` stories without pairs (`summary-story-no-pairs`).
  3. In `tests/test_legacy_feed_browser.py`, launch Chromium with `executable_path="/usr/bin/google-chrome"` when present.
- Why:
  1. Dynamic import failure previously left `voicePromise` resolving to `{}` and caused `class ReaderVoicePlayer extends VoicePlayer` to throw an unhandled TypeError, permanently breaking Listen until page reload. Resetting the failed promise with cache-busting retries allows immediate recovery once connectivity is restored.
  2. Routine updates periodically prune departed stories (such as `beb21be0b4`) from `data/news.json`, causing browser tests depending on live routine data to time out. Controlled fixtures ensure regression tests remain 100% deterministic and independent of scheduled data refreshes.
  3. Playwright in the test environment requires explicit pointing to the system Google Chrome binary.
- Alternatives rejected:
  - Showing an unrecoverable error banner on import failure: Degrades user experience when native speech synthesis is readily available on the device.
  - Relying on `voice/sample/news.json` fallback: Sample fallback lacks `summary_status` and cannot test routine feed adapter behaviors.

## D012 — Telugu Piper narration in a separate Pages checkout (2026-10-15, Codex)
- Decision: Keep content-addressed Telugu MP3s and a version-1 voice manifest in a separate `good-news-audio` checkout/Pages host. Generate only under `GOOD_NEWS_AUDIO=1`, after summarization, with Piper maya and ffmpeg mono 22.05 kHz/32 kbps. Retain current clips and seven days of unreferenced clips; publish helper commits only audio paths and pushes only with `--push`.
- Why: Family devices lack Telugu speech voices. Static MP3 playback works without installed voices, avoids paid APIs/runtime services, and keeps changing audio bytes outside the site history. A shared deadline, cached files, atomic writes and isolated failures preserve text publication. A small optional `data/audio-config.json` carries the host URL without touching news/cache schemas. The reader uses the existing module's text freshness checks and Telugu speech fallback, with a persistent bilingual unavailable message. Default English speech and the opt-in GV-2 English preview remain unchanged.
- Alternatives rejected: Committing audio into the site repo (history growth); hosted TTS APIs (network/cost); device-only Telugu speech (missing on target phones); enabling routine generation immediately (requires Anil's approval). Seven-day live-file cleanup cannot erase git history; compaction remains an operator maintenance task.
- Workflow: GN-6 was already claimed on `job/GN-6`. The explicit task instructions prohibit commits, branch changes, external writes, repo creation and network access, superseding general board checkpoint/commit rules. Browser test and four screenshot cases are provided; AF_INET socket creation is denied in this sandbox, so operator browser verification remains pending. Only one short real MP3 test fixture is stored here; unit tests use fakes.
